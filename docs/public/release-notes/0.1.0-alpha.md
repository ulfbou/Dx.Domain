# Dx.Domain 0.1.0-alpha

## Release status

`0.1.0-alpha` is the first public alpha of Dx.Domain. APIs, analyzer behavior, package composition beyond the locked four-package release boundary, and configuration remain provisional.

## Published packages

The release publishes exactly four packages at version `0.1.0-alpha`:

- `Dx.Domain.Annotations`
- `Dx.Domain.Kernel`
- `Dx.Domain.Primitives`
- `Dx.Domain.Facts`

`Dx.Domain.Analyzers` is not published as a standalone package. The authoritative analyzer assembly is embedded in each of the four packages at `analyzers/dotnet/cs/Dx.Domain.Analyzers.dll`.

`Dx.Domain.Generators` is not included in this release.

## Frameworks

- Annotations and the embedded analyzer target .NET Standard 2.0.
- Kernel, Primitives, and Facts target .NET 8, .NET 9, and .NET 10.

## Included capabilities

- explicit Result and domain-error values;
- runtime invariant and recoverable requirement mechanisms;
- strongly typed identity primitives;
- structural facts, transitions, and causation values;
- semantic annotations;
- compiler diagnostics delivered through each published package.

## Installation

Install only the package or packages required by the model. For example:

```bash
dotnet add package Dx.Domain.Kernel --version 0.1.0-alpha
dotnet add package Dx.Domain.Primitives --version 0.1.0-alpha
```

Add `Dx.Domain.Facts` for structural facts and causation. Add `Dx.Domain.Annotations` when semantic metadata is used directly. A standalone Analyzer package must not be installed for this release.

## Important limitations

This alpha provides compiler-assisted architectural governance, not formal verification. Static analysis does not comprehensively cover reflection, serializer materialization, dynamic invocation, unchecked assemblies, transitive Result correctness, invariant completeness, or business-semantic correctness. Consumers must evaluate serialization, input validation, runtime monitoring, and upgrade impact for their own workloads.

## Supply-chain disposition

Author signing is not required when the approved release signing disposition accepts NuGet.org repository signing. The release retains immutable pre-publication package identities and verifies public repository-signing status after ingestion.
