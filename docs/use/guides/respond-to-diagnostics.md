# Respond to Diagnostics

1. Open the matching page in the [diagnostic index](../../reference/diagnostics/index.md).
2. Confirm the project scope and configuration facts.
3. Correct the architecture or handling pattern.
4. Add a focused test.
5. Use suppression only when repository policy permits it and record the reason.

A warning is not proof that a violation is harmless. An error is not proof that all related misuse has been detected.
