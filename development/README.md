# DX Development
Status: Development index
Owner: Navigation and authority boundaries for continuing DX implementation planning
Scope: Reading order for implementation preparation and remaining-work documents

These documents guide realization of the Accepted product and architecture. They are not behavioral specifications, public schemas, release authority, or substitutes for `docs/ARCHITECTURE.md` and the Accepted ADRs.

## Reading order

1. [Realize implementation boundaries](implementation-architecture.md) defines internal dependency, capability, composition, and migration boundaries.
2. [Build verification evidence](verification-strategy.md) defines evidence classes and executable verification seams.
3. [Execute vertical implementation outcomes](implementation-plan.md) sequences independently verifiable implementation outcomes.
4. [Complete WS-005 through Accept Ready](remaining-work.md) defines the controlling remaining execution scope, acceptance criteria, release gates, Accept Ready decision, and Definition of Done after WS-001 through WS-004.

Begin with the normative authorities linked by each document. When planning and an owning authority differ, the owning authority governs and the planning document must be corrected.
